## 19_PASSWORD

## Disallow empty passwords:
## Allowing empty passwords widens the attack surface. See CVE-2020-27780 and dirtyfrag (CVE-2026-43284, CVE-2026-43500): a manipulated /etc/shadow combined with the nullok option in pam_unix can be used to bypass authentication.
## To disallow empty passwords, remove the nullok option from pam_unix in /etc/pam.d/system-auth. The two lines look like this afterwards:
sudo vim /etc/pam.d/system-auth
```ini
auth       [success=1 default=bad]     pam_unix.so          try_first_pass
password   required                    pam_unix.so          try_first_pass shadow
```

## List users with currently empty passwords:
getent shadow | awk -F: '($2=="") {print $1}'

## Configure password quality checks:
sudo vim /etc/security/pwquality.conf
```ini
minlen = 15
# digit
dcredit = -1
# uppercase
ucredit = -1
# lowercase
lcredit = -1
# Special character
ocredit = -1
# dictionary checks
dictcheck = 1
# username checks
usercheck = 1
usersubstr = 5
enforcing = 1
# check roots pwquality
enforce_for_root
```

## This file holds the system-wide defaults that are not easily expressed on the PAM line. Setting enforcing = 0 disables enforcement.
## Negative values like dcredit = -1 require at least one of the matching character class: digits, uppercase, lowercase, special characters. dictcheck = 1 and usercheck = 1 enable dictionary and username checks to block weak or related passwords.

## Make passwd enforce quality at change time. minlen=16 here and difok=6 (at least 6 characters must differ from the old password) apply immediately during password changes, beyond the pwquality.conf settings. yescrypt is stronger than sha512, so pam_unix uses it as the new hash format:
sudo vim /etc/pam.d/passwd
```ini
password required pam_pwquality.so retry=2 minlen=16 difok=6 dcredit=-3 ucredit=-2 lcredit=-2 ocredit=-3 enforce_for_root
password required pam_unix.so use_authtok yescrypt shadow
```

## Set the cost factor for yescrypt:
sudo vim /etc/login.defs
```ini
YESCRYPT_COST_FACTOR 11
```

## This file requires ENCRYPT_METHOD set to YESCRYPT, which is the Arch default. pam_pwquality(8) and pam_unix(8) are the man pages. Use strong passwords and a password manager. The Arch Wiki Security page goes in depth on this. Review group memberships and file permissions on sensitive system files regularly.

## Existing passwords are not rehashed automatically. Change every password after applying these settings. Do this from a root shell, from a user shell it does not update correctly somehow:
passwd $username

## Verify the change:
sudo cat /etc/shadow
## Look at the third field of an entry. For yescrypt, the encoded cost factor sits in the prefix: j9T is the default 5 rounds, jAT is 6, jBT is 7, jCT is 8, jDT is 9, jET is 10, and jFT is 11. Our factor 11 shows as jFT.
## Distributions without YESCRYPT_COST_FACTOR support can use the "rounds" option in PAM instead.

##On Arch a delay after failed logins is built in. If you do not use Arch Linux, add pam_faildelay to /etc/pam.d/system-login:
```ini
#auth optional pam_faildelay.so delay=5000000
```

## If you want to lock an account after 50 attempts instead of only a delay between 3 attempts, configure faillock. Open the file and set these options:
sudo vim /etc/security/faillock.conf
```ini
# Configuration for locking the user after multiple failed
# authentication attempts.
#
# The directory where the user files with the failure records are kept.
# The default is /var/run/faillock.
# dir = /var/run/faillock
#
# Will log the user name into the system log if the user is not found.
# Enabled if option is present.
audit
#
# Don't print informative messages.
# Enabled if option is present.
# silent
#
# Don't log informative messages via syslog.
# Enabled if option is present.
# no_log_info
#
# Only track failed user authentications attempts for local users
# in /etc/passwd and ignore centralized (AD, IdM, LDAP, etc.) users.
# The `faillock` command will also no longer track user failed
# authentication attempts. Enabling this option will prevent a
# double-lockout scenario where a user is locked out locally and
# in the centralized mechanism.
# Enabled if option is present.
# local_users_only
#
# Deny access if the number of consecutive authentication failures
# for this user during the recent interval exceeds n tries.
# The default is 3.
deny = 50
#
# The length of the interval during which the consecutive
# authentication failures must happen for the user account
# lock out is n seconds.
# The default is 900 (15 minutes).
# fail_interval = 900
#
# The access will be re-enabled after n seconds after the lock out.
# The value 0 has the same meaning as value `never` - the access
# will not be re-enabled without resetting the faillock
# entries by the `faillock` command.
# The default is 600 (10 minutes).
unlock_time = 86400
#
# Root account can become locked as well as regular accounts.
# Enabled if option is present.
even_deny_root
#
# This option implies the `even_deny_root` option.
# Allow access after n seconds to root account after the
# account is locked. In case the option is not specified
# the value is the same as of the `unlock_time` option.
# root_unlock_time = 900
#
# If a group name is specified with this option, members
# of the group will be handled by this module the same as
# the root account (the options `even_deny_root>` and
# `root_unlock_time` will apply to them).
# By default, the option is not set.
# admin_group = <admin_group_name>
```
